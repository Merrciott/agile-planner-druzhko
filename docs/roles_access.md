# Категории участников и права доступа

Планировщик как продукт предназначен одному пользователю. Таблица ниже описывает **участников разработки и работу с репозиторием**. На текущем учебном этапе фактический исполнитель один — Дружко Евгений Сергеевич; дополнительные роли являются моделью командного процесса.

| Категория | Что делает | Чтение | Изменение веток этапов | Слияние в `main` | Настройки репозитория |
| --- | --- | --- | --- | --- | --- |
| Владелец проекта | Определяет требования, принимает результат | Да | Да | Да | Да |
| Разработчик | Выполняет задачи и создаёт коммиты | Да | Да | Через запрос на слияние | Нет |
| Тестировщик/ревьюер | Проверяет сценарии и комментирует изменения | Да | При необходимости в отдельной ветке | Рекомендует, не утверждает | Нет |
| Наблюдатель | Просматривает публичный проект | Да | Нет | Нет | Нет |

Для учебного репозитория права выше представлены как **проектные правила**. Реальное разграничение прав на GitHub зависит от типа аккаунта, настроек репозитория и приглашения конкретных участников. Публикация репозитория сама по себе даёт чтение кода всем, но не даёт право изменять его содержимое.

Стабильная ветка `main` должна получать изменения после проверки. Ветки `phase/*` показывают жизненный цикл разработки и связывают коммиты с работами ИСР.
