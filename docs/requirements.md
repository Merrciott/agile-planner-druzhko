# Требования к личному Agile-планировщику

## Пользовательские сценарии

| ID | Сценарий | Критерий приёмки |
| --- | --- | --- |
| US-01 | Как пользователь, я добавляю задачу в бэклог или текущий спринт | Новая карточка появляется в нужной колонке и остаётся после обновления страницы |
| US-02 | Я задаю приоритет и оценку задачи | Карточка показывает выбранные значения |
| US-03 | Я перемещаю задачу между этапами | Статус меняется, а счётчики пересчитываются |
| US-04 | Я редактирую или удаляю задачу | Изменение сохраняется; перед удалением запрашивается подтверждение |
| US-05 | Я задаю цель и даты спринта | Настройки отображаются после повторного открытия страницы |
| US-06 | Я ищу задачи и фильтрую их по приоритету | Показаны только подходящие карточки; данные не удаляются |
| US-07 | Я создаю резервную копию и восстанавливаю её | JSON-файл содержит задачи и спринт; после импорта данные появляются в интерфейсе |

## Требования к данным и действиям

Задача содержит идентификатор, заголовок, описание, приоритет, оценку, принадлежность к спринту, статус и время создания. Заголовок обязателен, его длина ограничена 100 символами. Описание может занимать до 500 символов, оценка выбирается из набора 1, 2, 3, 5, 8 и 13. Доступны четыре статуса: бэклог, к выполнению, в работе и готово.

Кнопки карточки меняют статус на один шаг. При возврате в бэклог задача исключается из текущего спринта. Число выполненных задач и доля завершённых баллов рассчитываются только по задачам спринта. Изменения записываются в хранилище браузера после каждого действия.

Название спринта обязательно и ограничено 80 символами; цель необязательна и ограничена 300 символами. Даты можно оставить пустыми. Заполненные даты должны существовать в календаре; окончание не может предшествовать началу. При импорте JSON проверяются те же условия, допустимые поля задач и уникальность идентификаторов. Неверный файл не заменяет текущие данные.

## Работа в браузере

Программа запускается локально без сети и установки пакетов. Формы имеют видимые подписи, действия доступны через стандартные кнопки. На настольном и мобильном экране элементы должны оставаться доступными без горизонтального переполнения. Пользовательский текст вставляется через `textContent` и не исполняется как HTML. Для переноса данных на другое устройство используется экспорт JSON.

## Модель данных

Задача: `id`, `title`, `description`, `priority`, `points`, `status`, `inSprint`, `createdAt`. Спринт: `name`, `goal`, `startDate`, `endDate`. Все записи находятся в одном объекте версии 1, который сохраняется в `localStorage` и экспортируется в JSON.
