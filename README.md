# Личный Agile-планировщик

Учебный ИТ-проект по дисциплине «Проектная деятельность в ИТ». Вариант выбран по фамилии **Дружко**: буква «Д» входит в диапазон «В–Д», которому соответствует тема «Разработка программы планировщика Agile для личного пользования».

## Назначение

Планировщик помогает одному человеку вести список задач, выбирать задачи на текущий спринт, перемещать их по этапам работы и видеть прогресс. Данные хранятся в браузере на данном устройстве. Для резервной копии предусмотрены экспорт и импорт JSON.

## Запуск

Откройте файл `index.html` в современном браузере. Установка пакетов и подключение к серверу не требуются. Кнопка «Загрузить пример» создаёт учебные задачи для знакомства с интерфейсом.

## Возможности

- создание, изменение и удаление задач;
- доска со статусами «Бэклог», «К выполнению», «В работе», «Готово»;
- приоритет и оценка задачи в условных баллах;
- настройка цели и дат спринта;
- поиск и фильтр по приоритету;
- подсчёт выполненных задач и баллов текущего спринта;
- сохранение в `localStorage`, экспорт и импорт резервной копии JSON.

## Состав проекта

- `index.html`, `styles.css`, `app.js` — работающий прототип;
- `docs/project_charter.md` — основания и назначение разработки;
- `docs/requirements.md` — требования и критерии приёмки;
- `docs/wbs.md` — иерархическая структура работ по жизненному циклу ИС;
- `docs/roles_access.md` — категории участников и права;
- `docs/test_plan.md` — сценарии проверки;
- `docs/user_guide.md` — инструкция пользователя.

## Работа с Git

История ведётся в локальном Git-репозитории. Основная ветка `main` хранит согласованную версию. Ветки `phase/*` соответствуют этапам ИСР: требования, проектирование, разработка, проверка и выпуск. В учебном отчёте будут показаны настройка автора, состояние файлов, добавление в индекс, коммиты, ветки, подключение публичного удалённого репозитория и обмен изменениями.

## Ограничения

Прототип рассчитан на одного пользователя и один браузер. Очистка данных браузера удалит локальные задачи, если заранее не экспортировать резервную копию. Пользовательские аккаунты и сетевое взаимодействие не реализованы; роли в `docs/roles_access.md` описывают работу над исходным кодом проекта.
