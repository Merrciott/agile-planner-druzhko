# Agile-планировщик

Рейтинговая работа по дисциплине «Проектная деятельность в ИТ». Вариант: «Разработка программы планировщика Agile для личного пользования».

## Назначение

Планировщик помогает одному человеку вести список задач, выбирать задачи на текущий спринт, перемещать их по этапам работы и видеть прогресс. Данные хранятся в браузере на данном устройстве. Для резервной копии предусмотрены экспорт и импорт JSON.

## Запуск

Откройте файл `index.html` в современном браузере. Установка пакетов и подключение к серверу не требуются. Кнопка «Загрузить учебный пример» создаёт учебные задачи для знакомства с интерфейсом.

## Возможности и файлы

Задача содержит название, описание, приоритет и оценку в баллах. Карточки можно создавать, редактировать, удалять и перемещать между бэклогом, колонками «К выполнению», «В работе» и «Готово». Поиск и фильтр по приоритету ограничивают видимый список. Показатели спринта учитывают все его задачи, включая скрытые фильтром.

Спринт хранит название, цель и необязательные даты. Программа сохраняет изменения в `localStorage`. JSON служит резервной копией и позволяет перенести задачи в другой браузер.

Приложение состоит из `index.html`, `styles.css` и `app.js`. В каталоге `docs/` находятся основание разработки (`project_charter.md`), требования (`requirements.md`), проектирование (`design.md`), ИСР (`wbs.md`), план прав (`roles_access.md`), протокол проверки (`test_plan.md`) и инструкция (`user_guide.md`). Снимки сохранены в `report/screenshots/`, итоговый отчёт - в `report/Дружко_Е.С_git.docx`.

## Работа с Git

История ведётся в локальном Git-репозитории. Основная ветка `main` хранит согласованную версию. Ветки `phase/*` соответствуют этапам ИСР: требования, проектирование, разработка, проверка и выпуск. В отчёте приведены команды настройки Git, история веток и проверка опубликованного репозитория.

## Ограничения

Прототип рассчитан на одного пользователя и один браузер. Очистка данных браузера удалит локальные задачи, если заранее не экспортировать резервную копию. Пользовательские аккаунты и сетевое взаимодействие не реализованы; роли в `docs/roles_access.md` описывают работу над исходным кодом проекта.
